# Version Comparison

Generated by `scripts/compare_feature_versions.py` from snapshots in the feature store (`feature_store.store.get_version`), not recomputed. Consecutive versions are compared. There is no churn model yet, so each feature gets a simple risk flag; `churned` is joined only to describe how well each version's flag separates churners and is never a feature input.

> **Population and label.** Snapshots were built at as_of = 2026-05-03: 1,400 customers with `signup_date < as_of`, churn rate 11.1%. The rule `has_txn_history == 0 or days_since_last_txn >= 90` on these snapshots reproduces `churned` for 1,000 of 1,400 customers. (At 2026-08-01 the same rule matched 1,499 of 1,500, which is why feature_spec.md moved the training as_of to the start of the apparent 90-day label window.) Churn rates and AUCs below are single-date, univariate descriptions, not evidence that one version predicts better.

### Interpretation

- 838 of 1400 customers (59.9%) change value; Spearman rank correlation v1→v2 is 0.621.
- 388 customers cross the risk flag (no transaction in the window (value == 0)): 388 newly flagged, 0 no longer flagged.
- **Would a model notice?** Yes — enough customers move and the ranking reorders enough that a model trained on one version and scored on the other would see a different input distribution; the version must be pinned identically at training and scoring time (scripts/score_customer.py reads it from the store).
- Univariate AUC vs `churned` (descriptive only, see the note at the top): v1 0.441, v2 0.476.

- **v1 rationale:** Initial window: 90 days ending on the customer's last transaction. Customers who returned items in their most recent months may leave after a bad experience; a customer can be buying normally and still be unhappy with what they receive. A hypothesis the data does not yet support: at the training as_of, customers with any return churned at 9.8% against 10.6% without. Kept so a model can test it, and because returns can also mean an engaged customer.
- **v2 rationale:** Window extended from 90 to 180 days: returns are rare, so in a 90-day window the count is 0 for almost every customer (99th percentile is 1); 180 days picks up more returns and separates customers better.
